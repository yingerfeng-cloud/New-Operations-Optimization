供应商 `volcengine_ark`，用户既有模型 `doubao-seed-2-0-lite-260428`，实际协议 `responses_tools`。API Key 仅由本机文件读取，未进入提交。连接与 Function Calling 探测通过。

完整旅程使用合成的 3 台机组、4 个小时调度输入，通过真实模型创建优化任务、追问参数、拒绝缺少时段的数据、修正同一任务、等待明确确认、HiGHS 求解、解释、重复确认、供应商配置错误后恢复及取消。实际成本 **160300**，按独立成本排序分配和输入单价复算相同；功率、边界和爬坡最大残差均为 **0**。累计发电量为 **675 MWh**，各时段功率仍为 MW。没有用户确认前不求解，重复确认不增加求解任务。

真实执行暴露并修复的增量：

- 续接优先使用原任务已解析的 API Skill 名；内部场景名按注册表解析，避免 `economic_dispatch` 被当作不存在的调用名。保留 V3 任务身份、确认和执行边界。
- 初始机组出力已参与首时段爬坡，但原经济调度输入 schema 漏列，Agent 会丢弃用户输入。补为可选、按机组索引、单位 MW 的参数，并同步内置 Agent schema。不提供时保留原缺省行为。独立反例证明丢失初始出力会使本例变成 160700，不能只看 SUCCESS。
- 明确确认后的已完成结果原未传给后续对话，导致模型误称未求解。现提供最近完成任务的只读证据，包括冻结版本、输入、目标、变量和具体函数依赖；不将其恢复成可执行活动任务。
- 真实模型仍会将跨时段累计功率误写为 MW。增加已观察到的量纲错误检查，触发时用冻结证据生成事实答复，并记录 `power_sum_unit_mismatch`。实际最终答复使用 **675 MWh** 和 **160300**，错误文本不进入聊天记忆。这是针对该量纲错误的保护，不是所有 LLM 错误的通用证明。

本次用不存在的模型标识注入真实供应商配置错误。该回合保留 FAILED，永久错误的原回合重试按现有规则返回 409；修正配置后新回合调用真实模型成功，再取消待补参任务，未启动额外求解。未把它描述为同一回合的可重试传输错误。修复后解释在同一会话、同一已求解任务上续验，没有重新生成预期结果。记录见 `llm-live-probe.json`、`llm-live-journey.json`。

内置模型的既有发布记录未存 content hash，本轮如实保留 null，并对当次冻结的完整模型定义另记证据指纹，不伪造历史发布 hash。具体自建版本的非空内容 hash、函数组合及测试发布门槛由第一、二批已知答案验收覆盖。
