## 行为变化

- 参数 schema、运行入口和 Agent 共用允许格式及逐轴结构契约。显式 array/dict 类型继续限制格式；未定类型、有明确集合轴的索引参数描述已支持的数组/映射形式。返回轴顺序、成员、格式说明及示例。标量和无已知轴的参数不会一律开放双格式。服务和 Skill 参数说明展示同一契约。保留已有逐轴系数解析和时间归一化。
- 新模型版本及副本继承已有函数快照。函数更新候选只替换用户选定的具体修订，其他依赖的修订、hash、快照保持不变。候选通过真实测试后再应用；平台发布新版本，复用既有正式版本切换规则。未应用、失败和放弃均不改变原正式模型。
- 发布验证完整快照、契约、模型 hash 及有效测试证据，不比较函数库最新修订。库中新增修订仅是可用更新。主动更换候选依赖会清除测试证据，必须重测。用户不能通过普通模型写入请求伪造依赖快照或测试记录。
- 模型页提供修订/差异/更新测试/应用入口，候选提交标识保存在浏览器，连接不确定时重用标识。函数页按模型版本与任务列出修订，模型版本数与组件使用次数分开。被模型或任务引用的历史修订清理返回引用信息并拒绝删除。
- 一维默认使用 `segment_binary`，页面说明严格相邻分段 MILP。`sos2` 在现有 HiGHS 路径编译为等价分段二进制模型。历史 `convex_combination_lp`、`binary_segment_milp` 编码继续执行原有严格方法，诊断输出实际策略；不改写旧资产及其 hash。二维已有近似选项保持明确的非精确说明。

## 第 10 章任务及调用约定

| 操作 | 本批行为 |
| --- | --- |
| 提交、排队、运行 | 固定当次模型的完整依赖、归一化输入及求解配置 |
| 失败重试 | 新执行代次，复用原任务已准备的输入与快照；不重新读取库最新内容 |
| 历史重放 | `POST /api/tasks/{id}/replay`，生成新任务，沿用历史模型内容、输入及求解配置 |
| 采用新函数重算 | `POST /api/tasks/{id}/recalculate`，明确传入修订，创建候选版本和新测试任务；保留原任务和正式模型 |
| 固定 model_id / 固定 Skill | 不自动迁移。继续指向原版本，仍受原版本生命周期控制；旧正式版本被替换下线后固定调用按既有规则拒绝，历史复算用快照重放 |
| 正式服务 | `POST /api/tasks` 仅传 `model_code`，按既有活动 published 版本规则解析；新版本应用后切换到该版本 |

模型页更新测试 API 为 `POST /api/models/{id}/function-updates/test`，包含 `revisions` 及 `idempotency_key`；应用为候选 ID 的 `POST /api/models/{candidate}/function-updates/apply`。完整编辑仍沿用原模型版本工作台。函数 ID 不变时无需删除关联。
