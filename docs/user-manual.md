## 用户使用手册

> 文档版本：v1.0
>
> 编写日期：2026-08-03
>
> 适用范围：当前项目中的 React/Vite 正式前端、FastAPI 后端及本地运行环境

## 重要说明

本平台用于电力与能源场景的优化建模、求解、结果分析和辅助决策。平台输出的是优化建议和分析结果，不是自动控制指令；结果投入生产调度前，必须由具备业务权限的人员复核。

当前版本默认使用本地运行时存储，模型、任务和结果会写入项目数据目录。请在清理、迁移或重置运行环境前备份数据文件。

## 1. 平台简介

平台将业务场景、模型资产、运行参数、求解任务和结果分析串成一个闭环：

~~~mermaid
flowchart LR
    A[选择业务场景] --> B[选择或创建模型]
    B --> C[填写运行参数]
    C --> D[提交求解任务]
    D --> E[监控求解过程]
    E --> F[查看结果报告]
    F --> G[人工复核与业务决策]
    G -. 需要调整 .-> C
~~~

平台主要支持以下工作：

- 管理电力调度、储能、风光储、热电联产、梯级水电和市场交易等模型资产。
- 使用内置模板快速克隆模型，或通过五步工作流创建新模型。
- 使用通用线性 Builder、组件化 Builder 或模板 Builder 表达模型。
- 对模型的语义、公式、组件依赖、运行参数和求解器兼容性进行校验。
- 创建、监控、取消、重试和归档优化任务。
- 通过指标、曲线、业务解释、约束诊断和原始 JSON 查看结果。
- 使用模型服务、Skill 和 Agent 进行在线调用或自然语言交互。

### 1.1 求解器能力

| 问题或策略 | 默认求解器/处理方式 | 使用提示 |
| --- | --- | --- |
| LP | HiGHS | 适合连续线性模型 |
| MILP | HiGHS | 适合含整数变量的线性模型 |
| 一维 PWL | HiGHS + 分段线性展开 | 用曲线近似一维非线性关系 |
| 二维 PWL | HiGHS + 三角剖分 MILP | 会增加模型规模，应关注展开规模 |
| McCormick | HiGHS + 线性松弛 | 需要合理的变量上下界 |
| 连续变量 NLP | Ipopt | 通常是局部最优，结果依赖初值、上下界和模型缩放 |
| MINLP | 当前保留能力，不作为生产级能力开放 | 建议改用 PWL 或 McCormick 线性化 |

## 3. 环境准备与启动

### 3.1 运行要求

原生运行需要：

- Python 环境及项目依赖。
- Node.js 与 npm，用于运行 React/Vite 前端。
- HiGHS/highspy 和 Pyomo，用于线性或混合整数线性求解。
- 如果运行 NLP 模型，还需要可用的 Ipopt 可执行文件。

Docker 运行方式可统一封装 Python、Pyomo 和求解器环境。

### 3.2 安装后端依赖

在项目根目录执行：

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
~~~

安装前端依赖：

~~~powershell
cd frontend
Copy-Item .env.example .env -ErrorAction SilentlyContinue
npm ci
cd ..
~~~

安装前端依赖时优先使用 `npm ci`，以保证和锁文件一致。

### 3.3 快速启动核心平台

项目提供 Windows PowerShell 启动脚本：

~~~powershell
.\启动前后端.ps1
~~~

默认地址：

- React/Vite 前端：<http://127.0.0.1:5173>
- FastAPI 后端：<http://127.0.0.1:8000>
- 健康检查：<http://127.0.0.1:8000/api/health>

脚本支持的常用参数：

~~~powershell
.\启动前后端.ps1 -NoBrowser
.\启动前后端.ps1 -ApiPort 8001 -FrontendPort 5174
~~~

停止服务：

~~~powershell
.\停用前后端.ps1
~~~

脚本会将进程输出写入 `logs/`，并记录 PID 文件。端口被占用时，先执行停用脚本，或确认占用端口的进程确实属于当前项目后再处理。

> 注意：当前启动脚本将后端以 `SERVICE_MODE=platform` 启动，适合模型、任务、结果等核心平台功能。若需要完整使用 Agent 和 Skill，请按下一节使用 `combined` 模式启动。

### 3.4 启动完整平台（包含 Agent 与 Skill）

终端 1：启动后端。

~~~powershell
$env:SERVICE_MODE='combined'
$env:PORT='8000'
$env:OPTIMIZATION_PLATFORM_BASE_URL='http://127.0.0.1:8000'
$env:AGENT_PLATFORM_ACCESS_MODE='in_process'
$env:AGENT_ALLOW_IN_PROCESS_PLATFORM_FALLBACK='false'
.\.venv\Scripts\python.exe server.py
~~~

终端 2：启动前端。

~~~powershell
cd frontend
$env:VITE_API_BASE_URL='http://127.0.0.1:8000'
npm run dev -- --host 127.0.0.1 --port 5173
~~~

然后打开 <http://127.0.0.1:5173>。

如果修改了 `frontend/.env`，需要重新启动 Vite，环境变量才会生效。

### 3.5 生产托管模式

先构建前端，再由 FastAPI 托管 `frontend/dist`：

~~~powershell
cd frontend
npm run build
cd ..
$env:SERVICE_MODE='combined'
$env:PORT='8000'
.\.venv\Scripts\python.exe server.py
~~~

打开 <http://127.0.0.1:8000/>。生产托管模式下，React 页面和 `/api/*` 接口由同一个 FastAPI 服务提供。

### 3.6 Docker 启动

在项目根目录执行：

~~~powershell
docker compose build
docker compose up -d
~~~

默认访问：<http://127.0.0.1:18000>。

停止容器：

~~~powershell
docker compose down
~~~

Docker 模式使用项目根目录下的 `docker-data/` 持久化运行数据；原生模式默认使用 `data/`。

### 3.7 启动后检查

~~~powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
Invoke-RestMethod http://127.0.0.1:8000/api/solvers/status
~~~

健康检查至少应满足：

- `ok` 为 `true`。
- `pyomo_installed` 为 `true`。
- `highspy_installed` 为 `true`。
- LP/MILP 任务可使用 HiGHS。
- NLP 任务是否可用，以 `/api/solvers/status` 返回的 Ipopt 状态为准。

### 3.8 运行数据备份

默认运行时数据位置为 `data/runtime_store.json`。备份示例：
运行时存储当前使用 schema v4：启动时会把旧数据一次性规范化到当前结构，清理旧标记；之后新建的模型、任务、结果和 Agent 审计记录不会再写入旧标识。
如需迁移另一份历史数据文件，请先备份，再使用当前版本启动一次服务，确认服务正常后再继续使用该文件。

~~~powershell
if (Test-Path data\runtime_store.json) {
  Copy-Item data\runtime_store.json data\runtime_store.backup.json
}
~~~

请不要直接删除 `data/`、`docker-data/` 或 `runtime_store.json` 来解决普通界面问题；删除或替换它们可能造成模型、任务和结果记录丢失。

## 4. 界面基础操作

### 4.1 顶部状态栏

顶部状态区域会显示后端连接和求解器状态：

- “平台在线 · HiGHS”：后端可连接，默认线性求解器可用。
- “平台连接异常”：前端无法获取健康检查结果。
- “状态待检查”：页面正在初始化或等待接口返回。
- 点击状态标记可查看后端、求解器和运行环境明细。

右上角还包含：

- 全局搜索：搜索模型、场景、任务或报告；桌面端可使用 `Ctrl + K`。
- 任务消息：查看失败、无解或超时任务提醒。
- 业务视图 / 专家视图切换。
- “新建模型”快捷按钮。

### 4.2 侧栏与响应式布局

- 桌面端可折叠侧栏，折叠状态会保存到浏览器本地。
- 窄屏设备会将侧栏收进移动导航抽屉。
- 页面中的抽屉、弹窗和表格可横向滚动；提交前请确认没有被折叠区域隐藏的校验提示。

### 4.3 状态标签的基本含义

常见模型状态：

- 草稿：可编辑，尚未完成正式发布。
- 试运行：已通过测试，可按明确的 `model_id` 调试，但不会作为正式生产服务版本。
- 已发布：正式可调用版本，可进入任务、模型服务、Skill 或 Agent 调用链路。
- 已下线：保留历史记录，不再接受新的正式调用。

常见任务状态：

- `PENDING` / `QUEUED`：排队等待。
- `VALIDATING`：校验输入参数。
- `BUILDING_MODEL`：构建求解模型。
- `SOLVING`：调用求解器。
- `FORMATTING_RESULT`：整理结果和业务解释。
- `SUCCESS`：求解成功，可查看结果。
- `FAILED`：执行失败。
- `INFEASIBLE`：模型无可行解。
- `TIMEOUT`：超过允许的求解时间。
- `CANCELLED`：任务被取消。

## 5. 最快上手：从业务场景到优化结果

以下流程适合第一次使用平台的业务用户。

### 第一步：选择业务场景

1. 打开“业务场景”。
2. 找到目标业务，例如日前机组组合、经济负荷分配、储能充放电、风光储协同或梯级水电调度。
3. 查看场景下的模型数量、已发布模型和试运行模型。
4. 点击“使用推荐模型发起任务”。

如果场景没有可用推荐模型，可以点击“创建空白模型”，转入模型创建工作流。

### 第二步：选择模型并填写运行数据

1. 在“选择模型”步骤选择已发布模型。
2. 查看模型的适用场景、问题类型、时间维度和默认求解器。
3. 进入“填写运行数据”。
4. 按参数分组填写必填项和可选项。
5. 如有历史任务，可使用“从历史任务载入”。
6. 也可以展开“高级 JSON 输入”，粘贴参数对象并选择“导入并合并”。

### 第三步：检查并提交

1. 打开“检查并提交”。
2. 确认模型、调度周期、求解器和业务参数数量。
3. 阅读所有参数校验提示。
4. 确认提交内容预览后，点击“提交求解并打开详情”。

### 第四步：查看结果

任务成功后：

1. 在任务详情的“优化结果”或“业务解释”页签查看结果。
2. 在“结果分析”中打开归档报告。
3. 根据模型类型查看曲线、水库过程、出力与负荷、收敛诊断或业务建议。
4. 将结果交给业务负责人复核，不要直接把平台输出当成自动控制指令。

## 6. 业务场景库

入口：`/scenarios`。

业务场景库以业务问题组织模型，不要求用户先理解底层公式。场景卡片通常展示：

- 场景名称和描述。
- 场景下的模型资产数。
- 已发布模型数。
- 试运行模型数。
- 推荐模型。

### 6.1 使用推荐模型

当场景存在已发布推荐模型时，点击“使用推荐模型发起任务”，系统会把场景和模型带入任务创建向导。模型仍需在任务向导中读取运行参数契约并完成参数检查。

### 6.2 创建空白模型

当没有适用模型，或需要建立新的业务口径时，点击“创建空白模型”。进入模型工作台后需要自行定义场景、集合、参数、变量、公式、组件和运行参数。

### 6.3 当前常见场景

- 日前机组组合优化：机组启停、出力、备用和负荷平衡。
- 经济负荷分配：满足负荷平衡的机组经济出力分配。
- 储能充放电优化：充放电功率、SOC 和成本/收益协同。
- 风光储协同优化：新能源出力、弃电和储能响应。
- 梯级水电日前调度：水量平衡、库容、出力和上下游耦合。
- 热电协同优化：电功率、热功率和燃料消耗。
- 电力市场交易、碳排放优化等：以实际启用的系统字典和模型资产为准。

## 7. 模型资产中心

入口：`/models`。

### 7.1 查看和筛选模型

模型列表支持按以下条件筛选：

- 建模方式：通用线性 Builder、组件化 Builder、模板 Builder。
- 问题类型：LP、MILP、NLP 等。
- 模型状态：草稿、试运行、已发布、已下线等。
- 业务场景。

列表中的关键信息包括模型名称、编码、版本、场景、问题类型、求解器、状态和更新时间。

### 7.2 从内置模板克隆

1. 点击“从模板克隆”。
2. 搜索并选择一个内置模板。
3. 确认模板的名称、问题类型和求解器。
4. 点击确认克隆。
5. 克隆完成后进入模型详情或继续进入模型创建流程完善。

当前项目内置模板包括：

~~~text
unit_commitment_day_ahead
economic_dispatch
storage_dispatch
renewable_storage_dispatch
chp_dispatch
cascade_hydro_dispatch
pv_storage_capacity_planning
pv_storage_day_ahead_dispatch
pv_storage_intraday_dispatch
pv_storage_dispatch_v2
pv_storage_day_ahead_dispatch_v2
pv_storage_intraday_dispatch_v2
~~~

实际可见模板以服务端模板注册表和当前系统配置为准。

### 7.3 查看模型详情

点击“查看”后可查看：

- 基本信息：名称、编码、场景、状态、版本和发布时间。
- 模型语义：集合、参数、变量及时间维度契约。
- `generic_spec`：通用模型结构、约束和目标项。
- 组件装配：组件清单、依赖和参数绑定。
- 运行参数：输入 Schema、默认值和输入/输出契约。
- 模型说明：业务口径、建模方法和能力边界。
- 发布治理：测试、dry-run、发布信息、警告和版本治理。
- 调用记录：近期模型调用和任务记录。

可以在详情中切换“业务视图”和“专家视图”。

### 7.4 模型生命周期

推荐的生命周期为：

~~~text
草稿 -> 保存 -> 校验 -> 测试运行 -> 试运行 -> 正式发布 -> 新版本/下线
~~~

重要规则：

- 正式调用和 API/Skill/Agent 绑定只面向已发布版本。
- 试运行版本只能按明确的 `model_id` 调试，不会被生产调用自动选中。
- 模型通过测试后如果再次修改，测试状态会失效，必须重新保存并测试。
- 已发布版本不建议直接覆盖；后续修改应创建新版本或复制为独立模型。
- 下线只影响新的调用，历史任务和结果记录仍会保留。

## 8. 创建与维护模型：五步工作流

入口：`/models/create`，或从模型资产中心点击“创建模型”。

模型创建页底部提供“上一步”“下一步”“校验模型”“保存草稿”和“发布模型”等操作。页面底部状态会提示当前草稿是否已保存、是否存在阻断项以及最近测试是否仍然有效。

### 8.1 第一步：基础信息

配置内容：

- 创建方式：空白创建、从模板创建等。
- 业务场景。
- 建模骨架或模板。
- 建模模式：通用线性 Builder、组件化 Builder、模板 Builder。
- 模型名称。
- 模型说明。
- 模型编码。

建议：

- 模型编码保持稳定、唯一、便于接口调用；公式和外部绑定使用编码，不要依赖中文名称。
- 模型说明中写清业务目标、输入口径、时间范围、单位和结果用途。
- 如果从模板创建，先确认模板带入的集合、参数、变量、公式和运行参数，再开始修改。

### 8.2 第二步：模型语义

维护四类核心对象：

- 集合：例如机组 `unit`、调度时段 `time`、状态时点 `time_volume`。
- 参数：例如负荷、价格、容量、效率、来水和边界参数。
- 变量：例如出力、启停状态、SOC、库容和弃水量。
- 业务规则：用于描述边界、守恒、启停、上下游耦合等业务约束。

常见字段：

- 编码：公式、参数绑定和接口使用的技术标识。
- 名称：面向业务人员的可读名称。
- 维度：例如 `time`、`unit,time`。
- 单位：例如 MW、MWh、m³、元/MWh。
- 来源：运行时输入、静态参数、业务台账、系统生成等。
- 是否必填、默认值、示例值。
- 变量类型、上下界和索引。

时间维度约定：

- `time` 通常表示调度时段，长度为 `horizon`。
- `time_volume` 通常表示状态时点，长度为 `horizon + 1`。
- 来水、负荷、价格、出力等时序参数必须与模型的时间维度一致。

编码重复、维度缺失、变量引用未定义或时间集合不一致，都会在后续校验中形成阻断项。

### 8.3 第三步：数学展开

通用线性 Builder：

1. 在“目标函数”区域新增或编辑目标函数。
2. 在“约束条件”区域新增或编辑约束公式。
3. 使用结构化公式编辑器插入集合、参数、变量、常量、运算符和聚合结构。
4. 点击“编译模型（后端权威）”。
5. 在“编译预览”中确认变量、约束数量和 `generic_spec` 已生成。

示例公式：

~~~text
sum(p[u,t] for u in unit) >= load[t]
sum(cost[u] * p[u,t] for u in unit for t in time)
~~~

公式会同步保存展示公式、DSL 公式和结构化 token。聚合 `sum/min/max` 应使用编辑器提供的结构化聚合块。

组件化 Builder：

- 查看组件展开的约束、目标项、依赖关系和参数绑定。
- 在“函数映射”中绑定函数/曲线资产。
- 先处理缺失依赖、参数未绑定和函数资产校验失败，再进入发布校验。

当前会阻止通用线性模型发布的典型表达式包括：

- 未线性化的 `abs`。
- 直接使用值函数 `min/max` 或 `piecewise`。
- `!=` 不等式。
- 变量与变量相乘或相除。
- 右端表达式无法编译。
- 目标函数或约束缺少必要的关系符号。

如果业务关系确实是非线性的，应选择原生 NLP、1D/2D PWL 或 McCormick 等受支持的表达方式，而不是绕过校验。

### 8.4 第四步：运行参数

运行参数按以下类别组织：

- 运行时输入参数。
- 模型静态参数。
- 业务台账参数。
- 系统生成参数。
- 目标权重参数。

可使用：

- 逐项编辑。
- JSON 导入。
- 当前参数恢复。
- 结构预览。

JSON 根节点必须是对象，例如：

~~~json
{
  "load": [100, 120, 110],
  "price": [420, 680, 550]
}
~~~

导入后应检查：

- 参数编码是否存在。
- 必填参数是否已填写。
- 数组长度是否匹配 `horizon` 或 `time_volume`。
- 数值单位是否一致。
- 函数资产 ID、组件绑定和外部引用是否有效。

系统生成的时间字段由模型时间维度契约管理。不要为了绕过校验随意手工拼接 `time`、`time_volume` 或其他系统字段；应以页面显示的时间维度摘要和参数校验结果为准。

### 8.5 第五步：校验发布

发布前会统一检查：

- 基础信息。
- 语义结构。
- 公式。
- 组件依赖。
- 参数绑定。
- 运行参数完整性。
- 问题类型诊断。
- 求解器兼容性。

常用操作顺序：

1. 点击“校验模型”。
2. 对每一个“阻断”项点击“去修复”。
3. 返回对应步骤修改并保存。
4. 回到“校验发布”再次校验。
5. 点击“测试运行”。
6. 测试成功后，确认测试状态仍是当前版本。
7. 点击“发布模型”。

特殊边界：

- NLP 模型需要检测到 Ipopt。
- NLP 模型发布前需要确认“我理解 NLP 局部最优风险”。
- 包含整数变量和非线性表达式的 MINLP 会被标记为 `MINLP_RESERVED` 并阻止生产发布。
- 二维 PWL 采用精确三角剖分 MILP 时会增加二进制变量；展开规模超过默认阈值 4000 时会阻止发布或要求重新设计。

## 9. 创建求解任务

入口：`/tasks`，点击“创建任务”；首页也可点击“发起优化任务”。

任务向导包含三个步骤。

### 9.1 选择模型

下拉列表默认只显示可调用模型，通常包括已发布、活动、在线或就绪状态的模型。

选择模型后确认：

- 适用场景。
- 问题类型。
- 时间维度。
- 默认求解器。

如果模型运行参数契约加载失败，点击“重新加载契约”，不要在契约不可用时凭经验提交。

### 9.2 填写运行数据

任务参数工作区会按参数组显示输入字段，并提供：

- 业务参数分组导航。
- 全部、缺失、已修改等筛选。
- 手工编辑。
- 从历史任务载入。
- 高级 JSON 输入。
- 参数问题抽屉和定位。

模型类型与求解器通常对应关系为：

- LP/MILP/PWL/McCormick：HiGHS。
- 连续变量 NLP：Ipopt。

历史任务载入时，系统会尽量只应用当前模型认识的参数；未知参数会被忽略并在提示中说明。

高级 JSON 的根节点必须为对象，例如：

~~~json
{
  "load_forecast": [100, 120, 130],
  "electricity_price": [0.45, 0.72, 0.68]
}
~~~

导入后要打开检查抽屉，逐项处理“缺失”“格式错误”“维度不一致”和“时间维度不匹配”。

### 9.3 检查并提交

提交前会展示：

- 模型。
- 调度周期。
- 求解器。
- 已填写业务参数数量。
- 最终提交内容 JSON 预览。

确认无误后点击“提交求解并打开详情”。提交按钮不可用时，优先查看页面顶部的校验提示，不要重复点击。

## 10. 任务调度中心

入口：`/tasks`。

### 10.1 任务列表

任务列表展示：

- 任务编号。
- 模型。
- 状态。
- 进度。
- 创建时间。
- 求解器。
- 目标值。

任务状态会自动刷新。首页和顶部任务消息也会提示失败、无解和超时任务。

### 10.2 任务详情页签

打开任务的“查看”后，可切换：

- 任务概览：状态、模型、求解器、目标值、终止状态和约束违反摘要。
- 求解过程：排队、校验、建模、求解和结果整理的时间线。
- 输入参数：提交时实际使用的参数。
- 技术日志：后端和求解器日志。
- 优化结果：结构化变量和指标结果。
- 业务解释：面向业务的结论、风险和复核提示。

### 10.3 取消、重试和删除

- 仅运行中的任务可取消。
- 失败、无解、超时或已取消任务通常可以重试。
- 任务记录只有进入终态后才能删除。
- 删除任务记录会同时删除其归档结果，且不可撤销；删除前必须确认任务编号。

### 10.4 无解任务的处理顺序

1. 打开“任务概览”，查看约束违反摘要。
2. 打开“输入参数”，确认负荷、容量、上下界、初始状态和终端状态。
3. 打开“技术日志”，确认是否有参数维度错误或函数资产引用错误。
4. 检查时间维度是否满足 `time` 长度为 `horizon`、`time_volume` 长度为 `horizon + 1`。
5. 修正参数后重新创建任务，或使用“重试任务”验证同一输入是否为偶发错误。

## 11. 结果报告库

入口：`/results`。

只有求解完成并归档的任务会出现在结果报告库中。列表展示结果/任务编号、模型、目标函数值和 Gap。

> 不同模型的目标函数定义可能不同，目标函数值不应直接跨模型比较。

打开“查看报告”后，系统按结果能力动态展示页签，常见页签包括：

- 结果概览：目标值、运行时间、成功状态和关键指标。
- 变量曲线：出力、SOC、负荷等时间序列。
- 水库过程：库容、水位、流量、水量平衡和弃水等水电指标。
- 出力与负荷：电站出力、负荷曲线和对比关系。
- PWL 诊断：函数资产、三角面片、插值和线性化诊断。
- 收敛诊断：NLP、Ipopt、终止状态、局部最优提示和约束违反摘要。
- 业务建议：结果解释、风险提示和后续建议。
- 原始结果：完整 JSON，适合技术复核和接口排查。

当前版本的报告导出入口仍是预留能力；如需留档，可使用原始结果或系统提供的结果数据进行内部归档。

## 12. 组件资产与函数曲线

这些功能主要面向建模工程师和平台管理员，需切换到专家视图。

### 12.1 组件资产

入口：`/components`。

组件详情通常包含：

- required sets。
- 参数和变量。
- 生成的约束。
- 生成的目标项。
- 参数绑定。
- 组件依赖。
- 校验结果。

推荐操作顺序：

1. 查看组件启用状态和已有后端实现。
2. 打开详情，检查参数、变量和依赖。
3. 点击“校验组件”。
4. 修复缺失依赖、自依赖、循环依赖或绑定问题。
5. 校验通过后点击“发布组件”。
6. 如需保留旧版本，使用“复制版本”；不再参与新模型时使用“停用组件”。

停用组件不会自动删除历史模型和任务，但新模型装配时不应再依赖该组件。

### 12.2 函数与曲线资产

入口：`/functions`。

函数资产用于表达模型中的曲线映射和非线性关系，支持：

- 一维曲线 `y = f(x)`。
- 二维曲面 `z = f(x, y)`。
- 分段线性求解策略。
- CSV 导入、点数据编辑、曲线/曲面预览和诊断。

#### 新建一维曲线

1. 点击“新建函数资产”。
2. 函数类型选择“一维曲线 y=f(x)”。
3. 填写输入字段、输出名称和单位。
4. 添加至少两个点，或粘贴两列 `x y` 数据。
5. 按 `x` 排序。
6. 选择求解策略并保存。
7. 点击“校验”，确认资产状态不是无效。

#### 新建二维曲面

1. 函数类型选择“二维曲面 z=f(x,y)”。
2. 添加至少三个不重复的 `(x,y,z)` 点。
3. 规则网格建议至少提供四个点；非规则散点应提供可用的三角形索引或按界面诊断补齐数据。
4. 选择适合的二维求解策略。
5. 校验通过后查看着色曲面或三角网格预览。

#### CSV 导入

1. 点击“导入 CSV”。
2. 选择一维或二维函数类型。
3. 上传 CSV 或直接粘贴 CSV 内容。
4. 选择 `x`、`y`，二维时再选择 `z` 字段。
5. 查看字段识别和数据预览。
6. 点击“导入为草稿”。
7. 打开导入后的资产完成校验和后续绑定。

最小字段约定：

~~~csv
x,y
0,0
10,15
20,28
~~~

~~~csv
x,y,z
0,0,0
0,10,5
10,0,8
10,10,14
~~~

不允许重复的 `(x,y)` 点。函数资产如果校验失败，不能参与模型发布；请先查看校验错误和警告，再修改数据或求解策略。

入口：`/services`，兼容入口为 `/model-services`。

模型服务治理页面只展示已发布模型服务。可查看：

- 服务名称和模型编码。
- 服务状态。
- 推荐求解器。
- 输入参数契约。
- 输出参数契约。
- 调用记录。

### 13.1 在线调试

1. 选择一个已发布模型服务。
2. 查看输入契约和示例参数。
3. 将运行参数填写为 JSON 对象。
4. 点击在线调试。
5. 检查调试返回中的任务 ID、状态、问题类型、求解器和终止状态。

在线调试会真实调用后端能力，不要在生产参数未复核时直接执行高风险调用。

试运行模型不会自动出现在正式模型服务中；需要先完成发布治理。

## 14. Skill 服务中心

入口：`/skills`。

Skill 是模型服务化后的可治理调用单元。服务中心可查看：

- Skill 总数、启用数和停用数。
- 绑定模型和模型版本。
- Agent 是否绑定。
- 输入/输出 Schema 字段数。
- 最近调用、成功率和失败数。
- 平均耗时和异常 Skill。

### 14.1 Skill 详情

详情页签包括：

- 基础信息：Skill 名称、模型、端点、执行策略和人工复核要求。
- 输入 Schema：参数编码、类型、必填性、单位和维度。
- 生成与结果解释：SkillDefinition、定义 Hash、修订、生成方式和校验状态。
- 输出 Schema：结构化输出契约。
- Agent 绑定：Agent Skill 包、版本、状态和语义质量信息。
- 调用记录：调用 ID、状态、耗时和时间。

### 14.2 Skill 治理操作

- 启用/停用：控制 Skill 是否可调用；停用后仍保留治理记录。
- 同步：刷新模型契约和 Schema 信息。
- 生成完整 Skill：从模型契约生成输入、输出、指标和证据引用。
- 生成 Agent：创建或更新对应 Agent Skill 包。
- 校验人工修改：校验手工编辑的 SkillDefinition JSON。
- 保存为新修订：保留修改历史，不直接覆盖旧修订。

在线测试会执行真实 Skill。测试返回只用于辅助分析，不构成自动控制指令；高风险参数必须先人工复核。

## 15. Agent 工作台

入口：`/agents`。

Agent 工作台适合用业务语言提出优化需求，例如：

- “制定明日机组组合计划”。
- “优化储能充放电策略”。
- “分析中长期合同与现货敞口”。
- “生成梯级水电调度方案”。

### 15.1 标准操作流程

1. 点击“新建会话”。
2. 在输入框描述优化目标、时间范围和可用数据。
3. 点击“发送需求”；按 Enter 发送，按 Shift+Enter 换行。
4. 查看 Agent 识别的场景、匹配模型、参数完整度和工作流状态。
5. 如果 Agent 使用了默认值或示例值，检查“参数草稿”中的默认值、来源和完整度。
6. 点击“确认默认值”。
7. 所有必填参数齐全后，点击“提交优化任务”。
8. 查看返回的结构化结果、调用 ID、业务解释和人工复核点。

首页示例按钮只会把示例文本填入输入框，不会直接提交。

### 15.2 专家视图

点击“专家视图”后可以：

- 手工指定 Skill，或恢复自动识别。
- 查看平台连通性。
- 查看 Skill 列表及校验状态。
- 查看会话消息时间线。

### 15.3 Agent 安全边界

- Agent 不会替代人工调度决策。
- 默认值和示例数据必须经过确认。
- 调用前需要人工确认。
- 结果仅作为辅助分析和建议。
- 平台不会把 Agent 输出直接当作自动控制指令。

若出现 `PLATFORM_UNAVAILABLE`，通常是 Agent 后端无法访问平台后端。单体部署应确认使用 `SERVICE_MODE=combined`、`AGENT_PLATFORM_ACCESS_MODE=in_process`，并检查平台健康状态。

## 16. 求解环境与系统配置

### 16.1 求解运行环境

入口：`/runtime`。

可查看：

- 后端 API 是否连通。
- HiGHS 是否可用。
- Ipopt 是否可用。
- 任务服务是否连通。
- 当前前端入口和生产托管状态。
- 默认求解器与运行方式。

如果 Ipopt 不可用：

- LP/MILP/PWL/McCormick 任务仍可使用 HiGHS。
- NLP 模型不能假装成功，发布或运行会显示明确阻断信息。
- 可安装并配置 Ipopt，或把业务关系改为受支持的线性化策略。

### 16.2 系统配置

入口：`/settings`。

可维护内容包括：

- 服务连通性和状态总览。
- 业务场景字典。
- 组件领域和组件分类字典。
- 大模型 Provider、启用状态和连接测试。
- 部署入口和求解器配置说明。

修改业务场景字典后，模型创建页和业务场景库的可选项会随配置变化。没有启用任何业务场景时，空白建模流程不会回退到静态场景目录。

大模型密钥应通过环境变量或安全配置注入，不要写入前端代码、普通运行时 JSON、模型说明或提交到版本库。

## 17. 常见问题与故障处理

### 17.1 页面显示“平台连接异常”

检查：

~~~powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
~~~

如果失败：

1. 确认 FastAPI 进程正在运行。
2. 确认端口与前端 `VITE_API_BASE_URL` 一致。
3. 修改 `.env` 后重新启动 Vite。
4. 检查 `logs/` 中的后端错误日志。

### 17.2 模型、任务或结果列表为空

依次检查：

1. 后端是否以正确模式启动。
2. 是否打开了错误的端口或其他项目实例。
3. 是否切换到了会隐藏专家功能的业务视图。
4. 模型是否已发布；草稿和试运行模型不会作为正式调用模型使用。
5. 数据目录是否发生变化，原生模式和 Docker 模式的存储目录不同。

### 17.3 提交任务按钮不可用

通常是以下原因之一：

- 没有选择模型。
- 模型契约仍在加载。
- 模型契约加载失败。
- 必填参数为空。
- 参数类型不合法。
- 时序数组长度不匹配 `horizon` 或 `time_volume`。
- 函数资产或组件引用无效。

打开参数问题抽屉，点击具体问题进入对应字段，不要只修改 JSON 中的一个字段后反复提交。

### 17.4 模型发布被阻断

检查“校验发布”中的阻断项：

- 基础信息是否完整、编码是否唯一。
- 集合、参数、变量是否完整。
- 公式是否编译成功。
- 组件依赖和参数绑定是否通过。
- 运行参数是否完整。
- 当前问题类型与 HiGHS/Ipopt 是否兼容。
- 测试通过后模型是否又被修改过。

### 17.5 任务无解或求解失败

优先查看任务详情中的“任务概览”“求解过程”和“技术日志”。常见原因包括：

- 负荷超过所有资源的出力上限。
- 初始状态或终端状态与边界冲突。
- 上下界方向或单位填写错误。
- 约束时间维度少一项或多一项。
- 函数资产点重复、曲线不完整或二维三角形无效。
- NLP 缺少 Ipopt、初值或变量上下界。

修正输入后再新建任务或重试。重试前应确认失败不是由同一份错误参数造成的。

### 17.6 `PLATFORM_UNAVAILABLE`

单体 Agent/Skill 模式应使用：

~~~powershell
$env:SERVICE_MODE='combined'
$env:OPTIMIZATION_PLATFORM_BASE_URL='http://127.0.0.1:8000'
$env:AGENT_PLATFORM_ACCESS_MODE='in_process'
$env:AGENT_ALLOW_IN_PROCESS_PLATFORM_FALLBACK='false'
~~~

确认后端确实包含 Agent 和 Skill API，并重新创建会话或刷新页面。

### 17.7 Ipopt 不可用

打开 `/runtime` 查看 Ipopt 状态，或执行：

~~~powershell
python scripts/check_nlp_solver.py
~~~

如果只需要运行 LP/MILP，可以继续使用 HiGHS；如果必须运行 NLP，需要安装并配置 Ipopt，确认 Pyomo 能找到对应可执行文件。

### 17.8 二维 PWL 规模过大

二维精确 MILP 会按照时间点、设备数量和三角形数量扩展二进制选择变量。出现规模告警时，可考虑：

- 缩短调度时域。
- 减少网格点或三角形数量。
- 使用合理的函数资产和上下界。
- 评估非精确凸组合或 McCormick 策略是否满足业务精度。

### 17.9 生产模式刷新子路由返回 404

请先构建前端，再用 `server.py` 启动 FastAPI 托管模式：

~~~powershell
cd frontend
npm run build
cd ..
python server.py
~~~

开发模式下应通过 Vite 地址访问；生产模式下应通过 FastAPI 地址访问。

## 18. 推荐操作清单与能力边界

### 18.1 业务用户提交任务前

- [ ] 模型状态为已发布或当前允许调用状态。
- [ ] 调度周期和时间分辨率符合业务要求。
- [ ] 必填时序参数长度与时间维度一致。
- [ ] 输入数据单位、时间区间和版本已确认。
- [ ] 初始状态、终端状态和边界参数已复核。
- [ ] 提交前已阅读参数问题抽屉和 JSON 预览。

### 18.2 建模工程师发布前

- [ ] 模型编码唯一且稳定。
- [ ] 集合、参数、变量、单位和维度有完整说明。
- [ ] 公式已通过后端权威编译。
- [ ] 所有组件依赖和函数资产已校验。
- [ ] 运行参数 Schema 与示例值可复现一次真实任务。
- [ ] 已完成 dry-run 和测试运行。
- [ ] 测试通过后没有未重新测试的改动。
- [ ] 已确认问题类型、求解器和非线性处理策略。

### 18.3 结果复核时

- [ ] 检查任务状态和终止状态。
- [ ] 检查约束违反摘要。
- [ ] 检查关键变量曲线和边界是否合理。
- [ ] 检查目标函数的业务含义，不跨模型直接比较数值。
- [ ] NLP 结果确认局部最优风险。
- [ ] 水电、储能等模型确认库容、SOC、出力和守恒关系。
- [ ] 记录人工复核结论后再用于业务计划。

### 18.4 当前版本边界

- 结果导出按钮仍是预留能力，不作为主流程功能承诺。
- Monaco 编辑器未作为当前版本的必需依赖。
- Agent 和 Skill 的结果必须人工复核，不自动形成控制指令。
- MINLP 不作为生产级求解能力开放。
- NLP 的 Ipopt 结果不承诺全局最优。
- 正式功能以 `frontend/` 的 React/Vite 页面为准。
